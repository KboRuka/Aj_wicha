3. Prompt ที่ใช้กับ AI
จงสร้างโปรแกรมตรวจสอบรหัสผ่าน 2 เวอร์ชัน ได้แก่ JavaScript (ทำงานบน Node.js) และ Rust โดยปรับปรุงตามแนวทาง OWASP และต้องมีคุณสมบัติครบทั้ง 6 ข้อดังนี้:
1. รับค่า username (email) และ password จากผู้ใช้ผ่านหน้าจอคำสั่ง
2. ยอมรับรหัสผ่านที่มีความยาวตั้งแต่ 15 ตัวอักษรขึ้นไป
3. ไม่บังคับว่ารหัสผ่านต้องมีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก ตัวเลข หรือสัญลักษณ์พิเศษ
4. อนุญาตให้ใช้ช่องว่างและอักขระ Unicode (เช่น ภาษาไทย อีโมจิ) ได้ โดยห้ามนำช่องว่างหัวท้ายออกจากรหัสผ่านก่อนตรวจสอบ
5. รองรับรหัสผ่านที่มีความยาวอย่างน้อย 64 ตัวอักษรขึ้นไป และห้ามตัดรหัสผ่านให้สั้นลงโดยไม่แจ้งผู้ใช้
6. แสดงผลลัพธ์ว่าผ่านหรือไม่ผ่าน พร้อมระบุเหตุผลอย่างชัดเจน โดยห้ามพิมพ์ค่ารหัสผ่านออกมาซ้ำบนหน้าจอ และห้ามบันทึกรหัสผ่านลงไฟล์เด็ดขาด

4. ตัวอย่างจุดที่กลุ่มตรวจสอบและแก้ไขคำตอบจาก AI
 * การป้องกันการตัดช่องว่างหัวท้ายของรหัสผ่าน (Whitespace Handling)
   * สิ่งที่ตรวจสอบพบ: ในขั้นตอนการรับข้อมูลจาก Terminal โค้ดเริ่มต้นมักใช้คำสั่ง .trim() กับข้อมูลที่รับเข้ามาทั้งหมดเพื่อลบอักขระขึ้นบรรทัดใหม่ (\n) ซึ่งส่งผลให้ช่องว่างที่ผู้ใช้ตั้งใจใส่ไว้ด้านหน้าหรือด้านหลังรหัสผ่านถูกลบออกไปด้วย ขัดกับข้อกำหนดที่ห้ามนำช่องว่างหัวท้ายออกก่อนตรวจสอบ
   * การแก้ไข: ปรับโค้ดให้ใช้ .trim() เฉพาะกับ username ส่วน password ให้ใช้ .replace(/\r?\n$/, '') ใน Node.js และ .trim_end_matches(&['\r', '\n'][..]) ใน Rust เพื่อลบเฉพาะรหัสปุ่ม Enter ท้ายบรรทัดและรักษาช่องว่างหัวท้ายไว้ครบถ้วน
 * การนับจำนวนอักขระ Unicode ให้ถูกต้องตามจำนวนตัวอักษรจริง
   * สิ่งที่ตรวจสอบพบ: หากใช้ password.length ใน JavaScript โปรแกรมจะนับตามหน่วย UTF-16 code units ทำให้อีโมจิ 1 ตัว (เช่น 🚀) ถูกนับเป็น 2 ตัวอักษร และหากใช้ password.len() ใน Rust โปรแกรมจะนับเป็นจำนวน Byte (UTF-8) ทำให้พยัญชนะหรือสระภาษาไทย 1 ตัวถูกนับเป็น 3 Bytes ส่งผลให้รหัสผ่านที่สั้นกว่า 15 ตัวอักษรผ่านเกณฑ์อย่างไม่ถูกต้อง
   * การแก้ไข: ตรวจสอบและเปลี่ยนมาใช้ Array.from(password).length ใน JavaScript และ password.chars().count() ใน Rust เพื่อให้นับตามจำนวนตัวอักษร Unicode จริงเหมือนกันทั้งสองโปรแกรม
 * การตรวจสอบการปกปิดรหัสผ่านและการไม่บันทึกไฟล์ (No Echo & No File I/O)
   * สิ่งที่ตรวจสอบพบ: ตรวจสอบการแสดงผลลัพธ์ในทุกเงื่อนไข (ทั้งกรณีผ่านและไม่ผ่าน) เพื่อให้มั่นใจว่าไม่มีการแทรกตัวแปร password ลงในข้อความแจ้งเตือนเหตุผล และตรวจสอบว่าไม่มีการเรียกใช้ไลบรารีจัดการไฟล์ (fs ใน Node.js และ std::fs ใน Rust) ตามข้อกำหนด
